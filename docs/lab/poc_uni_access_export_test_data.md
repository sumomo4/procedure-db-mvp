# UNI抽出ファイルと案件化方式（lab・standard PoC）

## 構成

labとstandardを対象とする。本番サーバーは対象外。両環境のSSC参照データ・ユーザー・保存済み案件は保持し、環境間でコピーしない。

| 用途 | 配置先 |
| --- | --- |
| AccessDBの抽出4表 | `storage/lab/access_exports/uni/` |
| プレースホルダ設定 | `storage/lab/config/placeholder_mappings/uni.yml` |
| 案件化方式 | `storage/lab/config/case_doc_workflows/uni.yml` |
| ビル別命名規則・収容エリア表 | `storage/lab/config/case_doc_workflows/uni.xlsx` |

standardでは、上記の`storage/lab/`を`storage/standard/`へ読み替える。参照元DBの識別子は両環境とも`uni`で、設定・抽出ファイルはそれぞれの環境で管理する。2026-10-27にstandardへ同じ案件化方式とUNI用テスト入力を追加した。

命名規則は、提供された`Book1 2.xlsx`のコピー。元のダウンロードファイルは変更していない。設定Excelの数式や外部リンクは実行せず、「定義」シートのビル別接頭辞（B3:H24）と収容エリア表（S3:BA9）を読み取る。ホスト名の数式はサーバー側に移植した。

```yaml
version: 1
mode: uni
definition_file: uni.xlsx
```

方式設定がないDBは従来のユニット構成方式を使う。識別子の名前から方式を推測しない。命名規則Excelは設定フォルダ内のファイルだけを指定できる。

UNIにはユニット構成ファイルを要求しない。以前のPoCで追加した補助`ユニット構成.xlsx`は退避し、4表だけを参照する。旧補助ファイル用の4定義は削除せず無効化した。保存済み案件CSのスナップショットは保持する。

## 新規案件化

1. 参照元DBでUNIを選び、承認済み原本を指定する。
2. targetごとにブロック、ビル、クラスタ番号を指定する。targetごとに異なる値を指定できる。
3. 「対象装置を確認」でUSBE、USBH、USBM、USCEまたはUSLEのホスト名を生成する。
4. `TTS_定義.xlsx`と`装置追加.xlsx`のホスト名列に、一意に存在することを照合する。設置ビル・府県も確認する。不一致・欠落・重複は選択できない。
5. TTS_定義のTTSホスト名①②から、`TTS.xlsx`で照合できるTTSも候補に出す。
6. 各targetで1台以上を選ぶ。複数台や、別targetでの同一装置の再利用も可能。自動選択は行わない。
7. 置換結果を確認してExcelを出力、または案件CSを保存する。

プレビュー後に抽出ファイル・命名規則・マッピングが変わった場合は、再確認を求める。保存時にはtargetごとの対象工事・ホスト名・置換値を保持するため、後から参照ファイルを更新しても保存済み案件CSは変わらない。

## ホスト名の例

関西2 / 神戸中央 / CL4の場合、接頭辞`w28kc`から次を生成する。添付Excelの4ビル・28ホストの保存済み計算結果との一致を確認した。

| 装置 | 0系 | 1系 |
| --- | --- | --- |
| USBE | w28kcusbe100000 | w28kcusbe100100 |
| USBH | w28kcusbh140000 | w28kcusbh140100 |
| USBM | w28kcusbm141000 | w28kcusbm141100 |
| USCE | w28kcusce000200 | - |

関西1と他ブロック、CL16/17/19/20等の境界を分けて元の数式を再現する。提供マスターの収容エリア表はCL34までで、未設定記号のセルもある。未設定クラスタは選択候補に出さず、35・36を推測して補完しない。

## プレースホルダ

既存の装置別13定義を継続する。UNIのUSBE/USBH/USBM/USCE/USLEには、装置種別`UNI`の定義を共通適用できる。個別種別を指定した定義も使用可能。

- `UNI_SSH_IP`等: 選択したホスト名を、定義で指定した参照ファイル・キー列に照合する。
- `UNI_PRIMARY_TTS_IP`等: TTS_定義から直接取得する。
- `TTS_ADDRESS`: TTSそのものを選択したときにTTS.xlsxから取得する。
- `TARGET_DEVICE_HOSTNAME`: そのtargetで選択したホスト名。複数台の場合は改行で列挙する。
- `TARGET_BLOCK`、`TARGET_BUILDING`、`TARGET_PREFECTURE`、`TARGET_CLUSTER_NO`、`TARGET_AREA`: そのtargetの対象工事から取得する。

1targetに複数装置を選び、同じプレースホルダの値が装置ごとに異なる場合は、どれか1台を勝手に採用せず未置換とする。異なる値を個別に使う手順ではtargetを分ける。未置換が残る場合は確認チェック後にのみ出力・保存できる。

UNIでは「ユニット構成の値」を使用しない。旧4定義`UNI_CLUSTER_NAME`、`UNI_BLOCK`、`UNI_INSTALL_PREFECTURE`、`UNI_INSTALL_BUILDING`は無効化済み。対象工事には上記のtarget用プレースホルダを使う。設定画面の旧ユニットサンプル確認は表示せず、新規案件化の置換プレビューで確認する。

## 架空テストデータ

| ファイル | データ行 | 列数 |
| --- | ---: | ---: |
| TTS.xlsx | 12 | 2 |
| 収容エリア.xlsx | 3 | 37 |
| 装置追加.xlsx | 58 | 34 |
| TTS_定義.xlsx | 58 | 16 |

元の4ファイルの列名・列順・シート名を保持し、全カラムにテスト値を設定した。IPv4は文書用アドレス、IPv6は`2001:db8::/32`を使用する。ホスト名は提供された命名規則に従うが、接続情報はすべて架空であり本番接続に使用しない。

検証可能な組み合わせ:

- 関西1 / 京都 / CL2
- 関西2 / 神戸中央・湊川・滋賀大津・大安寺別館 / CL4
- 関西2 / 神戸中央 / CL17・19・20
- 九州 / 博多 / CL1

物理ホストが同じ場合は抽出表の行を重複させない。命名規則にある他のビル・クラスタは、対応する抽出データがなければ照合不可として表示する。

収容エリア.xlsxのCL列はエリア名でありホスト名ではない。旧PoCの誤ったホスト名サンプルを修正した。CL35・36など未設定値は明示し、候補には採用しない。

実データへの切替時は、4表のホスト名・設置情報と命名規則の一致を確認する。抽出ファイル・マッピング・命名規則を一組でバックアップし、テスト値を残したまま運用しない。
