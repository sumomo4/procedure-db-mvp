# Sprint 3 締めメモ

## 1. Sprint 3 のまとめ
Sprint 3 では、standard の主要データについて、参照中心の状態から「登録・更新・状態変更できる状態」へ進めた。

今回までに到達できたことは次のとおり。

- モジュール登録 API / WebUI
- 原本作成 / 更新 API / WebUI
- 承認状態変更 API / WebUI
- Excel取込の最小設計
- Excel helper / import API
- `xlsx / xlsm` 実ファイル取込の最小導線
- テストサーバーでの主要導線確認

---

## 2. できるようになったこと

### 2-1. モジュール
- 手入力でモジュールを登録できる
- 多装置の入力を保持できる
- Excel風の詳細表示で確認できる
- `xlsx / xlsm` を読み込んで登録画面へ流し込める

### 2-2. 原本
- 原本を新規作成できる
- 原本を更新モードで開ける
- 更新時は新しい draft 版として保存できる

### 2-3. 承認
- 承認対象を画面で選べる
- `draft -> published -> archived` の最小遷移を実行できる

## 4. Sprint 3 で残したもの

Sprint 3 で意図的に後ろへ回した論点は次のとおり。

- 原本詳細側の多装置表示の整え込み
- Excel完全再現の見た目調整
- 承認の複数選択 / 一括操作
- Excel取込後の原本連携やさらに広い運用導線
- 画面文言の細かい業務用語寄せ

---

## 5. Sprint 4 の入口

Sprint 4 の最初の入口としては、次を推奨する。

### 推奨入口
**SB4-01: 原本詳細側の多装置表示方針をモジュール詳細とそろえる**

理由:
- Sprint 3 でモジュール詳細側の多装置表示はかなり整った
- 原本詳細側がまだ完全には揃っておらず、レビュー時に差分として見えやすい
- Excel取込 / 原本 / 承認をつなぐ前に、閲覧体験を揃えておくと以降のレビューがしやすい
- UI の整合性を取ってから次の運用機能へ進んだほうが手戻りが少ない

---

## 6. Sprint 4 の入口タスク案

1. **SB4-01: 原本詳細の多装置表示統一**
   - 共通列 + 装置コマンド欄の構成をモジュール詳細に寄せる

2. **SB4-02: 原本詳細の装置コマンド欄アコーディオン整理**
   - Deviceごとの見やすさを改善する

3. **SB4-03: Excel取込結果から原本作成へつなぐ導線検討**
   - モジュール取込後の次操作を整理する

4. **SB4-04: 承認操作の複数選択方針整理**
   - 単票操作の次段として、一括操作の要件を決める

---

## 7. 現時点の判断

いまの時点では、Sprint 4 は次の順で入るのが自然。

1. 原本詳細の多装置表示統一
2. 原本 / Excel / 承認の導線整理
3. 承認の一括操作や運用補助へ広げる

この順なら、Sprint 3 で作った基盤の上に、見た目と運用の両方をきれいにつないでいける。
