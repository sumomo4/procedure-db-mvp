# 2026-04-21 Sprint 1 API基盤作業記録

## 目的

Sprint 1で作成したstandard側のWebUI、FastAPI、PostgreSQL基盤をテストサーバーへ配置し、関係者がブラウザから触れる状態にした。

今回のテストサーバーはDockerを使わず、Ubuntu 24.04 LTSへ直接配置する構成とした。

## デプロイ対象

- リポジトリ: `sumomo4/procedure-db-mvp`
- 対象領域: `standard`
- テストサーバー: `192.168.10.5`
- サーバーユーザー: `user`
- OS: Ubuntu 24.04.4 LTS
- 公開URL: `http://192.168.10.5/`

## 構成

```text
ブラウザ
  |
  | http://192.168.10.5/
  v
Nginx :80
  |-- /              -> /var/www/procedure-db-standard のWebUI静的ファイル
  `-- /api/          -> http://127.0.0.1:8000/api/
                         |
                         v
                      FastAPI
                      systemd: standard-api.service
                      listen: 127.0.0.1:8000
                         |
                         v
                      PostgreSQL
                      DB: mvp_standard
                      user: standard_user
```

## 設計方針

- WebUIはViteでビルドし、Nginxで静的配信する。
- APIはFastAPIをPython venv上で実行し、systemdで常駐化する。
- APIは外部へ直接公開せず、`127.0.0.1:8000` で待ち受ける。
- ブラウザからのAPIアクセスはNginxの `/api/` リバースプロキシ経由にする。
- WebUIのAPI呼び出し先は、テストサーバーでは同一オリジンの `/api/v1/...` を使う。
- PostgreSQLはUbuntu上の既存サービスを利用する。
- `lab` は個人研究用のため触らず、`standard` のみを対象にする。

## 変更内容

### WebUI

`apps/standard/frontend/src/App.tsx` のAPI base URL初期値を変更した。

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? "";
```

これにより、環境変数未指定時は同一オリジンの `/api/v1/health` と `/api/v1/health/db` を呼び出す。

ローカルでAPIを別ポート起動する場合は、従来通り `VITE_API_BASE_URL=http://localhost:8000` を指定すればよい。

### Ubuntuデプロイスクリプト

以下を追加した。

- `infra/ubuntu/setup_standard_server.sh`
- `infra/ubuntu/finish_standard_server.sh`

`setup_standard_server.sh` はUbuntu直載せ構成を最初から作るためのスクリプト。

`finish_standard_server.sh` は今回の作業中に、DB作成後の残作業を安全に再実行するため追加した仕上げ用スクリプト。DBスキーマ投入、systemd service作成、Nginx切替、疎通確認を行う。

### サーバーへ配置

