# SB3-13 確認観点整理

## 1. 目的
Sprint 3 で追加した API / WebUI / デプロイ改善について、確認観点を一度そろえる。
対象は standard のみとし、lab は今回の範囲に含めない。

---

## 2. 確認観点一覧

### 2-1. Backend pytest
- モジュール登録 API
  - `POST /api/v1/modules`
- 原本作成 / 更新 API
  - `POST /api/v1/source-docs`
  - `PUT /api/v1/source-docs/{source_doc_id}`
- 承認状態変更 API
  - `PATCH /api/v1/statuses/{target_id}`
- Excel helper / import
  - `excel_import.py`
  - `POST /api/v1/modules/import-sheet`
  - `POST /api/v1/modules/import`

確認したいこと:
- 正常系が通る
- 入力不正で 4xx が返る
- DB異常時に 5xx が返る
- 多装置 / 段落 / 空行スキップが壊れていない

---

### 2-2. Frontend build
- `apps/standard/frontend`
  - `npm run build`

確認したいこと:
- TypeScript compile error がない
- Vite build が成功する
- 最新 `dist/assets/*.js` が生成される

補足:
- Windows 環境では `spawn EPERM` が出ることがあるため、その場合は権限付き実行で再確認する

---

### 2-3. Docker ローカル確認
確認対象 URL:
- `/modules/register`
- `/modules/{id}`
- `/documents/create`
- `/documents/create?id={source_doc_id}`
- `/documents/{id}`
- `/approval`

確認したいこと:
- モジュール登録
  - 手入力で保存できる
  - 詳細画面へ遷移できる
- Excel取込
  - `Excel取込プレビュー` が動く
  - `Excelファイル取込` で `xlsx / xlsm` を読める
  - 取込結果が画面へ反映される
  - 手修正後に保存できる
- 原本作成 / 更新
  - 新規作成できる
  - 更新モードで既存原本を読める
- 承認
  - `draft -> published -> archived` の最小遷移ができる

---

### 2-4. DB schema / seed 確認
確認したいこと:
- 最新 schema が入っている
- モジュール詳細取得に必要な列が存在する
  - `device_headers_json`
  - `device_entries_json`
  - `indent_level`
- seed データが参照できる

補足:
- Docker の Postgres volume が古いと、保存や詳細取得が失敗する
- 必要に応じてローカル DB を作り直して schema を合わせる

---

### 2-5. テストサーバー確認
確認対象 URL:
- `http://192.168.10.5/modules/register`
- `http://192.168.10.5/modules/{id}`
- `http://192.168.10.5/documents/create`
- `http://192.168.10.5/documents/{id}`
- `http://192.168.10.5/approval`

確認したいこと:
- ローカルで通った最新 UI が配信されている
- 最新 bundle が `/var/www/procedure-db-standard` に反映されている
- 画面文言が極端に崩れていない
- 実ファイル取込が通る

補足:
- 表示差分がある場合は、次を確認する
  - `/home/user/procedure-db-mvp/apps/standard/frontend/dist/index.html`
  - `/var/www/procedure-db-standard/index.html`
  - 配信中 asset 名が一致しているか

---

### 2-6. Deploy script 確認
対象:
- `infra/ubuntu/setup_standard_server.sh`
- `infra/ubuntu/finish_standard_server.sh`

確認したいこと:
- shell syntax が崩れていない
- 静的 asset 配信確認が入っている
- API health の起動待ちが入っている
- デプロイ後に
  - `http://127.0.0.1:${API_PORT}/api/v1/health`
  - `http://127.0.0.1:${API_PORT}/api/v1/health/db`
  - `http://127.0.0.1/api/v1/health`
  を確認する

補足:
- 再起動直後は一瞬 `curl: (7)` が出ることがある
- 最終的に health が通ればタイミング差として扱う
