# SB1-06 / SB1-07 API構成方針

## 1. 目的

Sprint 1 の FastAPI 実装に向けて、プロジェクト構成、共通レスポンス、エラー処理の基本方針を整理する。

## 2. 対象

- SB1-06: FastAPIのプロジェクト構成方針を整理する
- SB1-07: 共通レスポンス / エラー方針を整理する

## 3. FastAPI構成

```text
apps/standard/backend/
├─ app/
│  ├─ core/
│  │  ├─ config.py
│  │  ├─ exceptions.py
│  │  └─ responses.py
│  ├─ db/
│  │  └─ connection.py
│  ├─ routers/
│  │  └─ health.py
│  └─ main.py
├─ tests/
├─ Dockerfile
├─ requirements.txt
└─ requirements-dev.txt
```

## 4. ルーティング方針

- API prefix は `/api/v1` とする
- Sprint 1 では基盤確認用として `/health` を実装する
- Sprint 2 以降は `modules`, `source-docs`, `statuses` などのリソース単位で router を追加する

## 5. 共通レスポンス方針

正常時は以下の形で返す。

```json
{
  "result": "success",
  "data": {},
  "message": "API is available."
}
```

異常時は以下の形で返す。

```json
{
  "result": "error",
  "data": null,
  "message": "PostgreSQL connection check failed."
}
```

## 6. エラー方針

- `HTTPException` は共通エラー形式に変換する
- リクエスト検証エラーは `400` とし、共通エラー形式に変換する
- DB接続確認の失敗は `500` とし、画面側で表示可能なメッセージを返す
- 詳細な調査情報は今後ログ出力で補完する

## 7. Sprint 1で実装したAPI

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/health` | API疎通確認 |
| `GET` | `/api/v1/health/db` | PostgreSQL接続確認 |
| `GET` | `/api/v1/modules/foundation` | Sprint 2向けモジュールrouter雛形確認 |
| `GET` | `/api/v1/source-docs/foundation` | Sprint 2向け原本router雛形確認 |
| `GET` | `/api/v1/statuses/foundation` | Sprint 2向け承認状態router雛形確認 |
